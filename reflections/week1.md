## The Four Process Activities: RetailSync Case Study

| Stage | Specification | Development | Validation | Evolution | 
|---|---|---|---|---| 
| Kickoff | Weak -requirements were only discussed verbally and no written requirements document was produced. | Present -the developer began designing the database schema. | Missing -there was no testing or checking with users. | Missing -no process for handling future changes was established. | 
| Development | Weak -developers relied on their understanding of the original meeting rather than clear requirements. | Present -the three developers built the different modules. | Weak -there was no proper code review or shared testing process. | Missing -there was no clear process for managing changes. | 
| Change of Plan | Weak -the second warehouse requirement was only mentioned in passing and was not properly added to the requirements. | Present -the existing design had to be redesigned for the second warehouse. | Missing -the new requirements were not properly tested. | Present but weak -the system needed to evolve, but the change was poorly managed. | 
| Testing | Weak -testing was based on the original requirements. | Present -developers fixed crashes found during testing. | Present but weak -developers tested it themselves, but warehouse staff did not. | Missing -testing problems were not used to make broader improvements before launch. | 
| Go-Live | Weak -the software did not match actual warehouse processes and barcode format. | Present -the completed system was deployed. | Weak -proper user testing should have identified the problems before deployment. | Present -the system was changed after the failures and the project was extended. | 

4. 

The failure that caused the most damage was the lack of proper specification at the beginning of the project. The requirements were discussed in one meeting but were never written down or properly confirmed with the people who would actually use the system. This caused problems later when the second warehouse was introduced and when the system was used by the warehouse staff. Proper requirements gathering and user involvement could have identified the different warehouse processes, barcode format and need for multiple users before development and testing were completed.
